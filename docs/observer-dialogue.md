# Observer-grounded dialogue

原生對話需由呼叫端明確開啟。在準備與提交 World turn 時，對同一個 session 傳入 `groundDialogueReferents: true` 與 `learnDialogueReferents: true`。既有預設模式不變。

- 角色從自身感知與已發生的對話建立指涉。僅有主題、指涉不明或話題轉換時，不用上一輪的物件記憶補空白。
- 名稱與別名要能辨認出完整指涉。「砂棠計時器二號」不會因為包含「砂棠計時器」就共用舊資料。沒有相符名稱時可先澄清，猜測仍然可以是角色的發言，但不會被這條學習路徑記成已確認的物件資料。
- 單靠「它」延續原生問答，需要同一場景和緊接的已提交對話。可以由原對話對象接續，也可以由已核實確實聽懂同一段前文的人接話。僅在場或聽成別的內容，不代表有共識。角色的舊記憶不會被刪掉，有明確名稱時仍可跨人物和場景回想。
- 角色已回答倒數問題，而原提問者實際聽見後立即說明自己指另一個已知名稱時，可接著回答原問題。更正的是對話指涉，不會重寫物件的既有記憶。
- 已辨認的證人明確表示「我剛才說錯了」並補充新地點時，角色保留舊證詞與新證詞，在新記憶中紀錄對舊記憶的撤回關係。只有相同證人、相同物件與相同資訊欄位能形成這種關聯。若只說「是西側醫務櫃」，也需要該證人在最近十分鐘內只有一筆可對應的地點證詞；不能把不相干的物件或其他人的話強行接起來。
- 後續地點回答必須經過角色自己的可用記憶與真正取回的片段。撤回的舊證詞仍可追溯，但不再當成當前答覆；不同證人的說法互相矛盾、同一證人未明確改口時，角色仍應表示不確定。
- 角色能針對不清楚的描述追問。後續的簡短回覆須來自原對話對象，且上一輪的追問須實際發出，才會延續該指涉。
- 回答區分當下看見、曾親眼看見與聽誰說過。過去讀到的面板數值不是即時狀態。複查需要實際選擇移動，由 World 判定是否成功，再由角色重新觀察。讀不到時會說無法確認。
- 回答與移動以候選動作呈現，仍由既有選擇、因果與提交流程處理。沒有新增客戶端預設值，也沒有更動站點部署。

執行 `node tests/run-communication.mjs` 可驗證對話邊界與原生 World 整合。新增回歸覆蓋指涉、澄清、來源驗證、回憶舊面板，以及走近後讀取、路徑阻擋、指涉變更和拒絕移動。
