# Character Runtime / Cognition 主工程接續基準

## 使用者目標（2026-09-13）

角色是在模擬一個持續存在的人。共用認知架構，但各自擁有獨立的自傳式記憶、人生經驗、信念、偏好、目標、主觀觀點與成長軌跡。決策要能受到「我是誰、經歷過什麼、相信什麼、想要什麼」影響。

下一階段以缺少的關鍵認知能力及能力之間的長期連續性為依據，不以增加單一模組複雜度為目標。依使用者指示，不依照專案 SKILL.md 選擇接續工作。

流程：檢查現況與缺口 → 研究其他人的方法 → 有限範圍實作 → 自我審核、修復及驗證 → 記錄結果與下一個缺口。使用者已授權自行審核及處理工程問題。

## 本輪缺口與研究

Phase85A–C 已將新經歷與舊記憶間的主觀衝突記錄為詮釋更新事件；尚無角色思考的讀取入口。Phase85D 要讓已提交的過往更新，在後續回合的既有 subjective cognition 入口提供「原先看法／後來的看法／兩者關係」。

研究來源（查閱日期：2026-09-13）：

- Hupbach et al. (2007), [Reconsolidation of episodic memories](https://pubmed.ncbi.nlm.nih.gov/17202429/), DOI 10.1101/lm.365707：提醒後的新學習可能影響後續回憶，實驗結果有時間與條件限制。
- Sederberg et al. (2011), [Human memory reconsolidation can be explained using the Temporal Context Model](https://pubmed.ncbi.nlm.nih.gov/21512839/), DOI 10.3758/s13423-011-0086-9：情境重建與項目—情境連結也能解釋相關現象；不能把觀察到的更新直接等同於細胞層級的再鞏固。
- Microsoft, [Event Sourcing pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)：不可變事件保留歷史，由讀取投影重建消費端需要的狀態；事件次序、重複處理與來源一致性需要明確處理。

工程選擇是上述方法的有限應用：保留原始記憶與詮釋演變，從已驗證事件建構角色可見的主觀歷程。這不是生物再鞏固模型，也不證明角色已具備完整真人認知。

## Phase85D 範圍

- 沿用 Phase65C 的已提交、同角色、非當回合的主觀觀點與關係讀取入口。只對該入口已選中的觀點與關係提供詮釋脈絡，不繞過它的數量上限。
- 更新事件、衍生索引、前後事件鏈及內嵌來源投影必須一致；記憶、回憶事件、主觀觀點與關係的來源必須吻合。
- 角色只看到原先看法、後來看法與候選關係；不輸出事件 ID、雜湊、記憶 ID、世界狀態或整份記憶庫。
- 「受到挑戰」仍是未解決的主觀衝突；候選 supersedes 不自動成為客觀真相或已採用信念。
- 不改寫原始記憶、不改變記憶強度、不增加回憶成功率、不強制選擇行動。
- Phase85A–C 的自動主循環寫入仍需另行整合。本階段處理已有提交事件的讀取，不宣稱整段生成／提交流程已自動運行。

## Phase85E：原生自動更新（2026-09-13）

研究後採用提交前暫存 domain events 的方式：在當回合主觀觀點與關係產生後，於既有 speculative World State 中建立詮釋更新，由原有 mutation executor 執行，與同一回合狀態及歷史一次提交。沒有新增背景訊息佇列。

參考 [Microsoft domain events](https://learn.microsoft.com/en-us/dotnet/architecture/microservices/microservice-ddd-cqrs-patterns/domain-events-design-implementation) 的延後分派與交易邊界，以及 [Chris Richardson transactional outbox](https://microservices.io/patterns/data/transactional-outbox.html) 的狀態／事件同交易原則；此處只有本機單一交易，不宣稱採用了跨服務 outbox 基礎設施。

已通過兩角色三回合原生測試：自動新增、提交故障回復、重試不重複、舊事件不覆寫、下一回合才讀取、原始記憶保留。多角色的衍生歷史索引合成單一 mutation，避免同欄位多次寫入被通用佇列重排。自我審核並補齊 world history 的新階段欄位白名單。

## Phase86：事件對個人目標的情緒性意義

現況：cognition.emotion 主要讀取既有狀態；Phase81 的 regret-like / relief-like 限於反事實比較。尚缺一般主觀經歷與當事人目標之間的評估來源，以及這些評估如何供後續思考取用。

研究（2026-09-13）：

- Marsella & Gratch (2009), [EMA: A process model of appraisal dynamics](https://people.ict.usc.edu/~gratch/CSCI534/Readings/COGSYS-RS-EMOTION-2008-6.pdf), DOI 10.1016/j.cogsys.2008.03.005：以個人對環境關係的解讀連接評估、應對與再評估。
- Scherer (2009), [Emotions are emergent processes](https://pmc.ncbi.nlm.nih.gov/articles/PMC2781886/), DOI 10.1098/rstb.2009.0141：事件對個人需求、目標與福祉的意義、應對可能性及隨情況改變的評估，是情緒過程的重要部分；情緒不能僅等同單一標籤。

Phase86A 的有限工程選擇：只輸入角色決策時已可見的目標，以及 Phase76A 給同角色的主觀行動後感受。角色解析器自行提出目標關聯、預期程度、感受到的應對可能性與簡短解讀；程式檢查來源、範圍與枚舉，不依成功／失敗標籤自動分配情緒。

Phase86B 接續方向：評估隨既有回合原子提交，後續思考只讀同角色近期且仍關聯目前目標的歷史感受；不把過往感受宣稱為當前固定心情，不自動衰減強度，不強制選動作，不新增人格或創傷診斷。

- 新增 goal_congruence、expectedness、coping_potential 與簡短主觀解讀，沒有硬編碼「失敗就悲傷」或情緒數值。
- 每次解析器僅收到單一角色、最多 8 個已可見目標與該角色的主觀結果。未知欄位、跨角色引用、重複評估及越權選動作會拒絕。
- 原生回合在有 affectiveAppraisalResolver 時產生評估，與來源 Phase76A 投影一併寫入原有 world history；缺少解析器或返回空判斷時，不自行發明感受。目前未新增公開 MCP 解析器工具。
- 後續準備回合最多提供 8 筆與目前目標文字精確匹配的歷史評估。角色思考與行動候選提案會收到此脈絡，Phase74 的 emotion_context 可引用該脈絡作為思考依據。

- 單元與原生兩角色三回合驗收已通過，涵蓋相同觀察的不同個人意義、前後應對評估變化、交易故障回復、同回合排除、角色隔離、目標不相關時不曝光及行動思考引用。

## Phase86C：依據自身經歷再評估（2026-09-13）

重新閱讀 Marsella & Gratch 的 [EMA 原文](https://people.ict.usc.edu/~gratch/CSCI534/Readings/COGSYS-RS-EMOTION-2008-6.pdf) 與 Scherer 的[動態情緒架構](https://pmc.ncbi.nlm.nih.gov/articles/PMC2781886/)，採取其中「個人對情境的解讀可隨經歷更新」的工程方向。這是有限的歷史脈絡與再評估連結，不是 EMA 全模型的復刻，也未實作完整應對策略選擇或生理情緒。

缺口：Phase86B 讓思考讀取過往感受，但新評估解析器只看當前目標與當回合經歷，尚不能知道自己之前怎麼看待同一件關切。

實作：

- 原生評估改用 Phase86C 情境版本，從已提交歷史重建同角色、與當前目標精確匹配的最近最多 8 筆主觀評估，與新經歷一併交給既有解析器。
- 解析器可以提供 reappraises_ref，明確引用自己對同一目標的舊評估。沒有明確判斷時不自動宣稱看法改變，不強迫反轉先前感受；跨角色、跨目標或不存在的引用會拒絕。
- 新評估追加在本回合交易中，不覆寫過去。回放時依時間順序逐筆重建來源；即使改寫先前脈絡後重新計算局部雜湊，仍必須與當時可見的已提交歷史一致。
- 舊版 Phase86A/B 記錄仍按原版本重建，新版使用獨立版本識別。角色決策包任意附加的情緒文字不會成為歷史依據。
- 歷史每次讀取仍需驗證已有回合；已改為單次掃描，每角色／目標保存最多 8 筆近期索引，避免每重建一回合都重新掃描全部前綴。尚未加入跨讀取快取或歷史分頁。

定向驗收已通過：11 回合兩角色、另有 20 回合三種目標交錯的時間順序驗證、相同目標不同個人歷史、看到新線索後的應對評估改變、舊版相容、JSON 重建、最近 8 筆限制、歷史回放排除未來、目標改變、跨角色／目標引用拒絕、偽造歷史脈絡拒絕。既有原生三回合測試亦加入真實前次引用，提交故障與重試仍通過。

本輪完整認知套件 149 個步驟一次通過，耗時 4 分 59.7 秒，包含先前逾時的 MCP 邊界探針，以及 Phase85E、Phase86A/B/C 最終版本。紀錄：tests/.tmp/phase86c-cognition-regression.log。

額外測試選擇器、分組清單、正式階段清單完整性與命令參數完整性檢查通過；全專案正式清單為 558 個步驟，本輪未執行全部 558 個。自我審核另補強解析器輸出欄位白名單，已驗證即使重新計算情境雜湊，嵌入於主觀經歷或目標中的額外私有欄位也不會轉交解析器。

公開 MCP 入口仍未提供新的評估解析器；實際生成評估需原生 affectiveAppraisalResolver。本輪使用確定性的測試解析器驗證能力串接，尚未證明實際模型會形成穩定、可信的長期情感變化。

接續工程的已知缺口：將這些評估與角色自己的應對意圖、計畫調整和後續結果形成可追蹤的循環；以及研究正式推理入口如何提供有來源約束的評估解析器。進入新階段前仍需重新研究方法並界定驗收，不把近期歷史讀取直接等同完整情緒或人格成長。


## Phase86D：把自己選擇的行動連進評估歷程（2026-09-13）

進入階段前重新研究 [Marsella & Gratch 的 EMA](https://people.ict.usc.edu/~gratch/CSCI534/Readings/COGSYS-RS-EMOTION-2008-6.pdf)，尤其是個人與環境的關係、行動及後續再評估之間的循環。也檢查 Phase74D 的既有行動承諾設計：它能證明角色選了哪個候選意圖，不能證明該選擇出於應對動機，也不能證明行動成功。因此本階段先補齊可驗證的「選擇—主觀結果—評估」連結。

- Phase86D 解析器現在同時收到自己選定的行動意圖、當回合主觀結果，以及過去相關評估中的行動經歷。
- 來源核對 Phase74D 正式承諾、世界／回合／狀態版本、Phase74A 候選行動內容引用、Phase76A 同角色同動作主觀結果。當前情境不得借用其他世界歷史或決策快照之後的回合。
- 新評估保存有限 action_experience；後續 Character Brain 與再評估解析器可讀取。原始候選詳細參數、引擎引用、其他角色狀態不會因這個欄位曝光。
- 選定行動與感受到自己有執行分開保存。performed=false 不會被選擇承諾覆蓋；未知執行狀態保持未知。chosen_as_coping_established 與 actual_effectiveness_established 均保持 false，尚未產生有效應對或因果功效判斷。
- 新版情境與投影採 Phase86D 版本；既有 Phase86A/C 評估不補造行動記憶，也不改寫舊紀錄。新舊混合歷史可從 JSON 重新建立。
- 沿用原生 affectiveAppraisalResolver 與原有回合原子提交，沒有新增解析器或公開 MCP 入口。

定向驗收已通過兩角色不同選擇、未執行狀態、跨回合行動記憶、拒絕全部候選、跨世界與未來回合排除、來源變造拒絕及舊版相容；原生多回合與提交故障／重試測試通過。完整認知回歸 150 個步驟一次通過，耗時 3 分 21.6 秒（tests/.tmp/phase86d-cognition-regression.log）。收尾另新增並通過未知執行狀態的定向案例；不會把選定意圖推定為已執行。

正式階段清單完整性、分組清單及命令參數完整性檢查通過。全專案清單為 559 個步驟，本輪未執行全部 559 個，也未進行實際模型長期生活品質驗證。自我審核修補跨世界歷史與決策快照之後的回合混入問題，相關拒絕案例通過。

接續缺口仍是角色自己明示「為何採取這個應對」及後續調整的循環。現有 Phase74D 只能證明候選行動的最終選擇；不能僅從感受與選擇同時出現推斷應對動機。下階段需先研究可由角色明示、來源受限且不取代既有計畫生命週期的接法。


## Phase86E：角色明示的應對意圖與後續經歷（2026-09-13）

進入階段前重新研究 [EMA 的 coping 段落](https://people.ict.usc.edu/~gratch/CSCI534/Readings/COGSYS-RS-EMOTION-2008-6.pdf)：應對可指向資訊、環境或個人的認知反應，且意圖與實際執行、有效性需要分開。工程採有限的五種描述類別（尋求資訊、改變情境、調節反應、尋求支持、等待觀察）；由角色明示，不依情緒模式替角色選策略。

實作：

- 原生 Character Brain 可在選擇候選行動時提供 coping_intention，引用當回合可見的自身過往評估，並填寫策略、理由與希望改變的事情。每角色每回合最多一筆，理由與希望改變的內容各最多 400 字元。
- 程式在因果模擬前驗證並固定這份明示意圖，核對同角色評估引用、候選行動及 Phase74D 選擇承諾。未提供理由就不建立應對意圖；無效資料在產生結果前拒絕。
- 依既有回合交易保存新 coping_intention_commitments。沒有 affectiveAppraisalResolver 或沒有新情緒評估時，應對意圖仍能保存，之後與 Phase76A 主觀結果一同讀回。
