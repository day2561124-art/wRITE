# PowerShell append-only recovery adjudication

PowerShell can launch detached work outside the Journal's artifact targets.
Empty targets, stopped processes and missing traces cannot prove no effect.
Future owner-loss recovery records `ambiguous_effect` for both the maintenance
child and outer MCP boundary before generic child/no-effect inference runs.
Unknown effects are never automatically replayed.

Legal legacy `operation_recovered/no_effect_observed` events remain immutable
valid history. They do not become freshly verified physical evidence. An
unresolved legacy shell query returns `recovery_required`, refuses reinitiation,
and disables automatic replay. This does not corrupt the otherwise valid chain
or require a blanket historical migration. New explicit ambiguous recoveries
still degrade Journal health until their actual effects are resolved.

The host-only `powershell_observed_test_effect` resolver accepts one narrow
reviewed detached-test profile. No MCP tool exposes a caller-selected profile,
arbitrary shell result, or generic no-child/no-effect resolver for this case.
Native maintenance uses existing project-write exclusion and durable audit;
Journal appends retain their own lock, identity validation and CAS. User
authorization remains the source of maintenance authority.

Evidence binds the original Pi claim and immutable action, parent/child identities
and terminal hashes, command fingerprint, owners/hosts, actual test start/end,
frozen workspace snapshot, and seven pinned physical artifacts: launcher, worker,
transfer manifest, claim, receipt, existing test runner and PowerShell module.
Live, foreign, missing, conflicting or changed evidence prevents adjudication.

Resolve the maintenance child first. The outer boundary requires that exact
durable child resolution and matching profile/claim/test identities. Append new
`pi_terminal_resolution` events and derive a completed effect, recording
`observed_effect:detached_all_gate_completed` and
`shell_exit_code_observed:false`. The test worker's observed exit code does not
prove the shell's exit code. Old events, including 54585/54586, remain unchanged.

The same canonical decision is idempotent; conflicting decisions fail. Typed
metadata and cold history decoding preserve the complete bounded record,
including a valid long reason. Published incomplete admissions remain available
for explicit continuation. An exact single unpublished resolver event may
advance the head only after full chain/history, original identity, quiescence,
dead-owner, profile and frozen physical revalidation. Unknown tails are never
deleted, truncated or reinterpreted. Recheck physical evidence at both append
boundaries.

After both exact effects are resolved, the original Pi call can use existing
reconcile-only with exact revision and owner. That recognizes the formal MCP
receipt without dispatch or replay. A separate new authorized plan preserves
the old operation and key.

Acceptance covers independent actual fixture workers and test-runner receipts,
child-first ordering, immutable legacy prefixes, cold decoding, duplicate and
conflicting decisions, forged hash/profile/context/artifact rejection, live
owners, competing work, and process exit at admission/completion and both
event-before-head cuts. Hash-valid forged fixture history must fail semantic
validation. Unit fixtures use their own tiny `all` definition and do not claim a
production full Gate. Production focused/regression/all and formal integration
Gates remain independently required.

Historical runner evidence remains pinned to the original ed1fff implementation
retained unchanged in frozen workspace59e4. Main can evolve its finite test
budget without changing the implementation evidence for54585/54586. The named
postseal Focused group has a ten-minute budget and adds reliable-execution and
metadata-rejection recovery cases. Predeployment official MCP/all cover those
cases before installation; the named gate is checked again after cold activation.

Large completed dev_run_tests responses retain the64KiB Pi receipt bound. A
read-only projection derives bounded facts only from one verified completed
child bound to fingerprint, workspace/workstream, suite, source snapshot, head,
manifest and order. Failed, recovered, absent, duplicate or foreign children
cannot prove PASS; proof includes event identities and hashes, never an invented
exit code or replayed test. Historical failed gates remain failed.

The full registered Focused suite remains nested in the wire lifecycle test.
Its observation bound derives from the fixed Focused registry plus five minutes;
the containing wire process gets that registry value plus ten minutes. The fixed
MCP registry has forty minutes, accounting for the observed1008s preceding

from that same registry. No suite, case or fault injection is removed.
